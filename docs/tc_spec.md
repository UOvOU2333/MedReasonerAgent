# 测试用例生成格式规范 (Test Case Generation Format Specification)

本文档严格定义了测试用例生成智能体输出的三种测试用例的格式、结构和内容要求。所有子智能体在生成测试用例时必须严格遵循此规范。

---

## 一、通用规范 (General Rules)

### 1.1 文档元信息

每份生成的测试用例文档必须在文件头部包含文档元信息表格：

```markdown
| 属性 | 内容 |
|------|------|
| **项目名称** | {project_name} |
| **文档类型** | 正常场景测试用例 / 边界场景测试用例 / 异常场景测试用例 |
| **文档版本** | V1.0 |
| **生成日期** | {YYYY-MM-DD} |
| **生成方式** | AI 自动生成（TCGen Agent） |
| **状态** | 草稿 |
| **DRG 版本** | CN-DRG 2018（基于项目内置 MDC/ADRG/CC 查表） |
```

### 1.2 命名规范

| 测试类型 | 文件名格式 | 示例 |
|----------|-----------|------|
| 正常场景测试用例 | `{project_name}_tc_normal_V{version}.md` | `MedReasonerAgent_tc_normal_V1.0.md` |
| 边界场景测试用例 | `{project_name}_tc_boundary_V{version}.md` | `MedReasonerAgent_tc_boundary_V1.0.md` |
| 异常场景测试用例 | `{project_name}_tc_abnormal_V{version}.md` | `MedReasonerAgent_tc_abnormal_V1.0.md` |

### 1.3 通用要求

- 所有文档使用 Markdown 格式
- 章节使用 `##` 二级标题，子章节使用 `###` 三级标题
- 表格必须对齐，使用标准 Markdown 表格语法
- 代码块必须指定语言（```json, ```text 等）
- 所有 AI 生成内容必须在文档末尾附加生成声明
- 文档末尾必须包含 `*本文档由 TCGen Agent 自动生成，状态为草稿，需人工审核确认。*`
- 每个测试用例必须有唯一编号（TC-N-XX / TC-B-XX / TC-A-XX）

## 二、DRG 分组规则引用

### 2.1 CN-DRG 2018 查表体系

测试用例生成基于以下 CN-DRG 2018 四层查表规则：

| 查表 | 输入 | 输出 | 说明 |
|------|------|------|------|
| MDC_TABLE | ICD-10 诊断编码前缀 | MDC 编码 + 名称 | 按前缀长度降序匹配，最长优先 |
| ADRG_TABLE | MDC + ICD-9-CM-3 手术编码前缀 | ADRG 编码 + 名称 | 手术前缀逐级截取（5→4→3→2位），无匹配回退内科 |
| CC_SET / MCC_SET | 次要诊断 ICD-10 编码 | CC / MCC / NONE | 精确匹配，MCC 优先于 CC |
| COMPLICATION_SUFFIX | 并发症等级 | DRG 后缀数字 | NONE→5, CC→9, MCC→1 |

### 2.2 DRG 入组核心逻辑

测试用例应围绕以下 CN-DRG 入组四步流程构建：

1. **确定 MDC** — 取主要诊断 ICD-10 编码前缀，在 MDC_TABLE 中按前缀长度降序匹配（如 K83.105 → K83 → MDCH，而非 K → MDCG）
2. **确定 ADRG** — 在该 MDC 下匹配手术编码前缀，命中则为外科 ADRG，未命中回退到内科 ADRG
3. **判定 CC/MCC** — 遍历次要诊断，先在 MCC_SET 查找，再在 CC_SET 查找，均无则 NONE
4. **组装最终 DRG** — ADRG 编码 + 并发症后缀数字 → 最终 DRG（如 GB2 + CC → GB29）

### 2.3 DRG 编码格式要求

- 最终 DRG 编码格式：`ADRG编码 + 数字后缀`
- 数字后缀含义：`5` = 无合并症(NONE)，`9` = 一般合并症(CC)，`1` = 严重合并症(MCC)
- 示例：`GB29`（胃手术+CC）、`HC15`（胆道手术+NONE）、`EC29`（胸壁手术+CC）
- **禁止使用 AR-DRG 风格的字母后缀（如 A/B）**

## 三、正常场景测试用例格式 (Normal Scenario Test Cases)

### 3.1 文件命名
`{project_name}_tc_normal_V{version}.md`

### 3.2 必须章节结构

```
## 1. 测试概述
### 1.1 测试目标
### 1.2 测试范围
### 1.3 参考资料

## 2. DRG 分组规则摘要
### 2.1 知识图谱关系
### 2.2 入组判定逻辑

## 3. 测试场景设计
### 3.1 场景分类
### 3.2 场景覆盖矩阵（表格：场景编号 | 诊断 | 手术 | MDC | ADRG | 并发症 | 最终DRG | 覆盖说明）

## 4. 测试用例
### 4.X 各测试用例详细设计
（每个测试用例含：编号、名称、描述、输入数据、预期输出、测试步骤）

## 5. 测试数据
### 5.1 病历样本汇总
### 5.2 预期 DRG 分组映射表
```

### 3.3 测试用例表格格式

每个正常场景测试用例必须包含：
```markdown
| 属性 | 内容 |
|------|------|
| **用例编号** | TC-N-XX |
| **用例名称** | (简短描述) |
| **测试场景** | (诊断+手术组合描述) |
| **前置条件** | (输入数据准备要求) |
| **输入数据** | 见下方病历 JSON |
| **预期 DRG 分组** | (预期的 DRG 编号和名称) |
| **预期置信度** | 高 / 中 / 低 |
| **测试步骤** | 1. ... 2. ... 3. ... |
| **预期结果** | (系统行为描述) |
```

### 3.4 病历 JSON 格式

所有测试用例的"输入数据"必须使用以下 CN-DRG 病历 JSON 格式（对齐 `entity._parse_emr()` 解析器）：

```json
{
  "性别": "男",
  "年龄": 65,
  "主要诊断": {
    "疾病名称": "急性透壁性心肌梗死",
    "疾病编码": "I21.3"
  },
  "次要诊断列表": [
    {"疾病名称": "2型糖尿病", "疾病编码": "E11.9"},
    {"疾病名称": "原发性高血压", "疾病编码": "I10"}
  ],
  "主要手术": {
    "手术名称": "冠状动脉支架植入术",
    "手术编码": "36.06001",
    "手术级别": 3
  },
  "其他手术列表": [
    {"手术名称": "冠状动脉造影", "手术编码": "88.55001", "手术级别": 2}
  ]
}
```

**字段说明**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `性别` | string | 是 | `"男"` 或 `"女"` |
| `年龄` | int | 是 | 患者年龄（0-120） |
| `主要诊断.疾病编码` | string | 是 | ICD-10 编码，用于 MDC 判定 |
| `主要诊断.疾病名称` | string | 是 | 诊断中文名称 |
| `次要诊断列表` | array | 否 | 次要诊断数组，用于 CC/MCC 判定 |
| `主要手术.手术编码` | string | 否 | ICD-9-CM-3 编码，用于 ADRG 判定 |
| `主要手术.手术名称` | string | 否 | 手术中文名称 |
| `主要手术.手术级别` | int | 否 | 1-4 级手术 |
| `其他手术列表` | array | 否 | 额外手术/操作数组 |

### 3.5 内容规范

- 至少生成 8 个 TC-N-XX 编号的测试用例
- 覆盖至少 3 种不同的 MDC（如 MDCF 循环系统、MDCE 呼吸系统、MDCG 消化道、MDCH 肝胆胰、MDCI 骨骼肌肉）
- 覆盖至少 3 种不同的手术/操作类型（如心血管手术、消化系统手术、骨科手术）
- 覆盖至少 2 种并发症等级（CC 和 NONE，含后缀 9 和 5 的 DRG）
- 覆盖至少 2 种 DRG 分组类型（内科 ADRG + 外科 ADRG）
- 每个用例的"输入数据"必须包含完整的 CN-DRG 病历 JSON 结构
- 预期 DRG 分组必须使用 CN-DRG 数字后缀格式（5/9/1），禁止使用字母后缀

## 四、边界场景测试用例格式 (Boundary Scenario Test Cases)

### 4.1 文件命名
`{project_name}_tc_boundary_V{version}.md`

### 4.2 必须章节结构

```
## 1. 测试概述
### 1.1 测试目标
### 1.2 边界定义

## 2. 边界条件分析
### 2.1 合并症影响分析
### 2.2 年龄边界分析
### 2.3 多手术组合影响

## 3. 测试场景设计
### 3.1 边界场景矩阵（表格：场景编号 | 边界类型 | 变化因素 | 预期影响）

## 4. 测试用例
### 4.X 各边界测试用例详细设计

## 5. 测试数据
### 5.1 边界病历样本
### 5.2 对比分析表
```

### 4.3 测试用例表格格式

每个边界测试用例必须包含：
```markdown
| 属性 | 内容 |
|------|------|
| **用例编号** | TC-B-XX |
| **用例名称** | (简短描述) |
| **边界类型** | 合并症有无 / 年龄边界 / 多手术 / 性别差异 |
| **变化因素** | (说明哪个变量在边界上变化) |
| **基线场景** | TC-N-XX (引用的正常场景编号) |
| **变化描述** | (与基线的差异) |
| **输入数据** | 见下方病历 JSON（格式同 3.4 节 CN-DRG 格式） |
| **预期 DRG 变化** | (DRG 后缀变化，如 HC15→HC19 表示 NONE→CC) |
| **测试步骤** | 1. ... 2. ... 3. ... |
| **预期结果** | (系统行为描述) |
```

### 4.4 边界类型覆盖要求

| 边界类型 | 最少用例数 | 说明 |
|----------|-----------|------|
| 合并症有无 | 2 | 同一诊断添加/移除 CC 编码 → DRG 后缀 5↔9 变化 |
| 年龄边界 | 2 | 测试年龄阈值（如 17/18 岁、新生儿/成人） |
| 多手术组合 | 1 | 多个手术同时存在时的优先级判定（主要手术优先） |
| 性别差异 | 1 | 仅与性别相关的 MDC 分组（如 MDCM/MDCN） |

## 五、异常场景测试用例格式 (Abnormal Scenario Test Cases)

### 5.1 文件命名
`{project_name}_tc_abnormal_V{version}.md`

### 5.2 必须章节结构

```
## 1. 测试概述
### 1.1 测试目标
### 1.2 异常分类

## 2. 异常条件分析
### 2.1 编码错误类型
### 2.2 信息缺失类型
### 2.3 逻辑冲突类型

## 3. 测试场景设计
### 3.1 异常场景矩阵（表格：场景编号 | 异常类型 | 触发条件 | 预期系统行为）

## 4. 测试用例
### 4.X 各异常测试用例详细设计

## 5. 测试数据
### 5.1 异常病历样本
### 5.2 错误处理验证表
```

### 5.3 测试用例表格格式

每个异常测试用例必须包含：
```markdown
| 属性 | 内容 |
|------|------|
| **用例编号** | TC-A-XX |
| **用例名称** | (简短描述) |
| **异常类型** | 编码错误 / 信息缺失 / 逻辑冲突 / 格式错误 |
| **触发条件** | (输入中存在什么问题) |
| **输入数据** | 见下方病历 JSON（含错误，基础格式同 3.4 节 CN-DRG 格式） |
| **预期错误码** | (系统应返回的错误类型) |
| **预期错误信息** | (用户可见的错误提示) |
| **预期系统行为** | 拒绝入组(DRG=N/A) / 标记异常 / 降级到NLP模式 / 提示缺失 |
| **测试步骤** | 1. ... 2. ... 3. ... |
| **预期结果** | (系统行为描述) |
```

### 5.4 异常类型覆盖要求

| 异常类型 | 最少用例数 | 说明 |
|----------|-----------|------|
| 编码错误 | 2 | 无效 ICD 编码（如 "XXXX.9" 不在 MDC_TABLE），get_mdc() 返回 None |
| 信息缺失 | 2 | 缺少"主要诊断"字段，entity._parse_emr() 返回 None |
| 逻辑冲突 | 1 | 诊断与手术逻辑不匹配（如产科诊断+骨科手术） |
| 格式错误 | 1 | JSON 格式错误（如字符串截断）、字段类型错误（年龄="六十八"） |

## 六、文档质量检查清单

TCGen Agent 的 reviewer 子智能体在审核文档时必须逐项检查：

| 检查项 | 检查内容 | 要求 |
|--------|----------|------|
| CHK-01 | 文档元信息表 | 必须存在，字段完整 |
| CHK-02 | 所有必须章节 | 按类型检查章节完整性 |
| CHK-03 | 表格格式 | Markdown 表格对齐正确 |
| CHK-04 | 编号连续 | TC-N/TC-B/TC-A 编号无跳号 |
| CHK-05 | 无占位符 | 不得有 TODO、TBD 等占位标记 |
| CHK-06 | 语言一致 | 中文文档全文使用中文 |
| CHK-07 | 结尾声明 | 必须包含 AI 生成声明 |
| CHK-08 | 病历 JSON 完整 | 每个用例含完整 CN-DRG 病历 JSON（字段: 性别/年龄/主要诊断/次要诊断列表/主要手术/其他手术列表） |
| CHK-09 | 用例数量达标 | 正常≥8个、边界≥7个、异常≥7个 |

## 七、虚拟文档系统存储规范

测试用例存储遵循与文档生成相同的规范：

- 存储路径：`{project_root}/generated_docs/{project_name}_{tc_type}_{version}.md`
- 索引文件：`generated_docs/index.json`
- 同名覆盖前备份为 `{filename}_backup_{timestamp}.md`
- tc_type 取值：`tc_normal` / `tc_boundary` / `tc_abnormal`
