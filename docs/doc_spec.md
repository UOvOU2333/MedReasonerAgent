# 文档生成格式规范 (Document Generation Format Specification)

本文档严格定义了文档自动生成智能体输出的三种文档的格式、章节结构和内容要求。所有子智能体在生成文档时必须严格遵循此规范。

---

## 一、通用规范 (General Rules)

### 1.1 文档元信息

每份生成的文档必须在文件头部包含文档元信息表格：

```markdown
| 属性 | 内容 |
|------|------|
| **项目名称** | {project_name} |
| **文档类型** | 需求分析文档 / 架构设计文档 / 测试文档 |
| **文档版本** | V1.0 |
| **生成日期** | {YYYY-MM-DD} |
| **生成方式** | AI 自动生成（DocGen Agent） |
| **状态** | 草稿 |
```

### 1.2 命名规范

| 文档类型 | 文件名格式 | 示例 |
|----------|-----------|------|
| 需求分析文档 | `{project_name}_requirements_analysis.md` | `MedReasonerAgent_requirements_analysis.md` |
| 架构设计文档 | `{project_name}_architecture_design.md` | `MedReasonerAgent_architecture_design.md` |
| 测试文档 | `{project_name}_test_plan.md` | `MedReasonerAgent_test_plan.md` |

### 1.3 通用要求

- 所有文档使用 Markdown 格式
- 章节使用 `##` 二级标题，子章节使用 `###` 三级标题
- 表格必须对齐，使用标准 Markdown 表格语法
- 代码块必须指定语言（```python, ```bash, ```json 等）
- 禁止在文档中使用未定义的缩写
- 所有 AI 生成内容必须在文档末尾附加生成声明
- 文档末尾必须包含 `*本文档由 DocGen Agent 自动生成，状态为草稿，需人工审核确认。*`

## 二、需求分析文档格式 (Requirements Analysis Document)

### 2.1 文件命名
`{project_name}_requirements_analysis.md`

### 2.2 必须章节结构

```
## 1. 引言
### 1.1 编写目的
### 1.2 适用范围
### 1.3 术语与缩写

## 2. 系统概述
### 2.1 项目背景
### 2.2 系统定位
### 2.3 建设目标
### 2.4 系统边界

## 3. 用户需求分析
### 3.1 目标用户角色
### 3.2 用户场景分析
### 3.3 用户故事（表格：编号、角色、需求描述、优先级、验收条件）
### 3.4 用例分析（至少3个用例，每个含：编号、名称、参与者、前置条件、基本流程）

## 4. 功能需求
### 4.X 各功能模块
（每个功能含：编号、描述、输入、输出、处理逻辑、约束条件）

## 5. 非功能需求
### 5.1 性能需求
### 5.2 可用性需求
### 5.3 可靠性需求
### 5.4 可维护性需求
### 5.5 安全需求

## 6. 数据需求
### 6.1 数据模型
### 6.2 数据流

## 7. 外部接口需求
### 7.1 API 接口
### 7.2 数据交换格式

## 8. 约束与假设
### 8.1 技术约束
### 8.2 业务约束
### 8.3 假设条件
```

### 2.3 内容规范

- **用例分析**：每个用例使用标准表格格式（编号、名称、参与者、前置条件、触发条件、基本流程、异常流程、后置条件）
- **功能需求**：每个功能需求必须有唯一编号（FR-XX），含完整的输入/输出/处理逻辑描述
- **用户故事**：优先级使用 高/中/低 三级，验收条件必须可验证

## 三、架构设计文档格式 (Architecture Design Document)

### 3.1 文件命名
`{project_name}_architecture_design.md`

### 3.2 必须章节结构

```
## 1. 总体架构
### 1.1 架构风格
### 1.2 系统架构图（ASCII 或文本描述）
### 1.3 技术栈总览

## 2. 模块划分
### 2.1 模块总览（表格：模块名、目录/文件、职责、依赖）
### 2.2 各模块详细设计

## 3. 数据流设计
### 3.1 核心数据流图
### 3.2 状态管理
### 3.3 事件机制

## 4. 组件/服务通信
### 4.1 同步通信（REST API 定义）
### 4.2 异步通信（WebSocket / 事件总线）
### 4.3 模块间数据契约

## 5. 技术选型
### 5.1 后端技术
### 5.2 前端技术
### 5.3 基础设施
### 5.4 选型理由（表格：技术项、选型、理由、替代方案）

## 6. 部署架构
### 6.1 部署拓扑
### 6.2 环境配置
### 6.3 部署流程

## 7. 安全设计
### 7.1 安全边界
### 7.2 数据保护策略
```

### 3.3 内容规范

- **架构图**：使用 ASCII art 或结构化文本描述，至少包含3层：展示层、业务逻辑层、数据层
- **模块设计**：每个模块必须包含职责说明、输入输出接口、依赖关系
- **接口定义**：REST API 使用标准表格（方法、路径、请求体、响应体、说明）

## 四、测试文档格式 (Testing Document / Test Plan)

### 4.1 文件命名
`{project_name}_test_plan.md`

### 4.2 必须章节结构

```
## 1. 测试策略
### 1.1 测试层次（单元测试 → 集成测试 → 系统测试 → 验收测试）
### 1.2 测试方法（黑盒/白盒、手动/自动）

## 2. 单元测试方案
### 2.1 测试范围
### 2.2 测试用例（表格：编号、模块、测试项、输入、预期输出）
### 2.3 覆盖率目标

## 3. 集成测试方案
### 3.1 集成策略
### 3.2 接口测试用例（表格：编号、接口、测试场景、请求、预期响应）
### 3.3 数据流验证

## 4. 系统测试方案
### 4.1 功能测试
### 4.2 性能测试
### 4.3 安全测试
### 4.4 兼容性测试

## 5. 验收测试方案
### 5.1 验收标准（checkbox checklist 格式）
### 5.2 验收流程

## 6. 测试环境
### 6.1 硬件环境
### 6.2 软件环境
### 6.3 测试数据

## 7. 缺陷管理
### 7.1 缺陷等级定义
### 7.2 缺陷跟踪流程
```

### 4.3 内容规范

- **测试用例**：每个测试用例必须有唯一编号（TC-XX），包含明确的可验证预期结果
- **验收标准**：使用 checkbox 格式 `- [ ]` ，每项可独立验证
- **覆盖率目标**：必须量化（如"代码行覆盖率 >= 80%"）
- **缺陷等级**：定义 P0/P1/P2/P3 四级，含响应时间要求

## 五、文档质量检查清单

DocGen Agent 的 reviewer 子智能体在审核文档时必须逐项检查：

| 检查项 | 检查内容 | 要求 |
|--------|----------|------|
| CHK-01 | 文档元信息表 | 必须存在，字段完整 |
| CHK-02 | 所有必须章节 | 按类型检查章节完整性 |
| CHK-03 | 表格格式 | Markdown 表格对齐正确 |
| CHK-04 | 编号连续 | FR/TC 编号无跳号 |
| CHK-05 | 无占位符 | 不得有 TODO、TBD 等占位标记 |
| CHK-06 | 语言一致 | 中文文档全文使用中文 |
| CHK-07 | 结尾声明 | 必须包含 AI 生成声明 |

## 六、虚拟文档系统存储规范

虚拟文档系统智能体在保存文档时遵循以下规则：

### 6.1 存储路径
```
{project_root}/generated_docs/{project_name}_{doc_type}_{version}.md
```

### 6.2 索引文件
在 `generated_docs/` 目录下维护 `index.json`：
```json
{
  "documents": [
    {
      "name": "MedReasonerAgent_requirements_analysis",
      "type": "requirements",
      "version": "V1.0",
      "created_at": "2026-06-08T00:00:00Z",
      "path": "generated_docs/MedReasonerAgent_requirements_analysis_V1.0.md",
      "status": "draft"
    }
  ],
  "last_updated": "2026-06-08T00:00:00Z"
}
```

### 6.3 文件操作规则
- 同名文件覆盖前必须备份为 `{filename}_backup_{timestamp}.md`
- 每次写操作后更新 `index.json`
- 禁止删除 `index.json` 中的历史记录，只能追加或标记 `archived`
- 保存文件名格式：`{project_name}_{doc_type}_V{version}.md`
